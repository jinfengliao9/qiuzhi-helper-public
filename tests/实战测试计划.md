# 求职工作区Skill - 实战测试计划

## 一、测试目标

1. **验证规范化整改效果**：在真实环境中验证8阶段整改后的功能是否正常、稳定
2. **发现潜在问题**：在实际使用中发现单元测试和端到端测试未能覆盖的问题
3. **验证用户体验**：从用户视角验证操作流程是否顺畅、文档是否清晰
4. **持续性优化**：建立问题发现→记录→整改→验证的闭环机制
5. **为多平台扩展做准备**：验证核心模块稳定性，为后续扩展奠定基础

## 三、测试阶段

### 阶段一：核心功能验证（第1-2天）

**目标**：验证整改后核心功能是否正常运行

**测试任务**：
1. **简历生成测试**
   - 修改resume_data.json中的内容
   - 运行`python job_search.py resume`
   - 检查4套HTML是否生成
   - 检查PDF是否生成、样式是否正确
   - 检查头像是否显示
   - 检查内容是否完整、无溢出

2. **职位匹配评估测试**
   - 准备一个真实的JD文本
   - 运行`python job_search.py rank --jd test_jd.txt`
   - 检查JD解析是否准确
   - 检查4维度评分是否合理
   - 检查匹配度报告是否生成
   - 检查投递建议是否合理

3. **工作流引擎测试**
   - 运行`python job_search.py --help`，检查12个命令是否完整
   - 运行`python job_search.py config show`，检查配置显示
   - 运行`python job_search.py validate`，检查数据验证
   - 运行`python job_search.py quality check`，检查质量门禁
   - 运行`python job_search.py jobs list`，检查岗位库列表
   - 运行`python job_search.py jobs report`，检查报告生成
   - 运行`python job_search.py outcome list`，检查申请归档

4. **自动化测试回归**
   - 运行`python tests/run_tests.py`
   - 确认33个测试全部通过

**验收标准**：
- 所有核心功能正常运行
- 无致命错误
- 自动化测试全部通过

### 阶段二：岗位采集实战（第3-5天）

**目标**：在真实招聘平台上测试岗位采集功能

**测试任务**：
1. **智联招聘抓取测试**
   - 确认Browser Use浏览器登录态
   - 设置搜索关键词（如"测绘工程师"）
   - 设置筛选条件（城市、薪资、经验、学历）
   - 抓取10-20个岗位
   - 检查岗位列表提取是否完整
   - 检查详情提取率（工作职责、任职要求）
   - 检查薪资解析是否正确
   - 检查反爬控制是否有效（无验证码、无风控）

2. **BOSS直聘抓取测试**
   - 确认Browser Use浏览器登录态
   - 设置搜索关键词（如"测绘工程师"）
   - 设置筛选条件（城市、薪资、经验、学历）
   - 抓取10-20个岗位
   - 检查岗位列表提取是否完整
   - 检查详情提取率
   - 检查薪资提取（特殊字体问题）
   - 检查技能标签提取
   - 检查反爬控制是否有效

3. **多平台合并测试**
   - 抓取智联和BOSS各10个岗位
   - 合并到岗位库
   - 检查去重是否正确（BOSS优先）
   - 检查来源标签是否正确
   - 生成多平台联合报告
   - 检查报告中公司链接和岗位链接是否按平台区分

4. **匹配引擎测试**
   - 对抓取的岗位进行匹配度评估
   - 检查匹配度区分度（不应全部85分或全部56分）
   - 检查高匹配岗位是否真的匹配
   - 检查低匹配岗位是否真的不匹配

**验收标准**：
- 两个平台都能正常抓取
- 详情提取率≥70%
- 无风控触发
- 多平台合并去重正确
- 匹配度区分度合理

### 阶段三：完整求职流程测试（第6-7天）

**目标**：模拟真实求职流程，端到端测试所有功能

**测试任务**：
1. **完整流程模拟**
   - 从岗位库中选择一个感兴趣的岗位
   - 运行`python job_search.py rank`评估匹配度
   - 根据匹配度决定是否投递
   - 运行`python job_search.py apply`生成定制简历
   - 检查定制简历是否突出了与岗位相关的经历
   - 运行`python job_search.py interview`准备面试
   - 检查面试问题是否针对该岗位
   - 运行`python job_search.py outcome add`添加投递记录
   - 检查记录是否正确添加
   - 模拟收到面试通知，运行`python job_search.py outcome update`更新状态
   - 检查状态更新和历史记录
   - 运行`python job_search.py outcome stats`查看统计
   - 检查统计数据是否正确

2. **质量门禁集成测试**
   - 在每个步骤后运行`python job_search.py quality check`
   - 检查质量门禁是否能发现潜在问题
   - 模拟数据错误，检查质量门禁是否能发现
   - 修复问题后重新检查，确认通过

3. **文档可用性测试**
   - 按照`references/快速入门指南.md`操作，检查是否能快速上手
   - 按照`references/sop/`中的SOP操作，检查步骤是否准确
   - 遇到问题时查阅`references/FAQ.md`，检查是否有解决方案
   - 记录文档中不准确、不清晰、缺失的内容

**验收标准**：
- 完整流程顺畅，无卡点
- 质量门禁能有效发现问题
- 文档能指导用户完成操作
- 用户体验良好

### 阶段四：压力测试和边界测试（第8天）

**目标**：测试系统在边界条件和压力下的表现

**测试任务**：
1. **大数据量测试**
   - 岗位库增加到200+岗位
   - 测试报告生成速度
   - 测试匹配度计算速度
   - 测试岗位库列表显示

2. **异常数据测试**
   - 简历数据缺少必填字段，检查错误处理
   - 岗位数据格式错误，检查验证工具
   - 配置文件格式错误，检查配置加载
   - JD文本格式异常，检查解析能力

3. **网络异常测试**
   - 抓取过程中断网，检查恢复能力
   - 页面加载超时，检查重试机制
   - 登录态过期，检查提示和处理

4. **重复操作测试**
   - 多次运行简历生成，检查是否有冲突
   - 多次添加相同投递记录，检查去重
   - 多次抓取相同岗位，检查岗位库去重

**验收标准**：
- 大数据量下性能可接受
- 异常数据有友好的错误提示
- 网络异常能正确处理，不崩溃
- 重复操作有去重机制

## 四、问题记录和整改流程

### 4.1 问题分类

| 级别 | 定义 | 响应时间 | 示例 |
|------|------|----------|------|
| P0-致命 | 功能完全不可用、数据丢失、系统崩溃 | 立即修复 | 简历生成失败、岗位库损坏 |
| P1-严重 | 核心功能异常、结果错误、用户体验严重受损 | 24小时内修复 | 匹配度计算错误、报告链接失效 |
| P2-一般 | 非核心功能异常、结果有偏差、用户体验一般 | 3天内修复 | 面试问题不够精准、样式小问题 |
| P3-轻微 | 文案错误、样式微调、优化建议 | 下个版本修复 | 文档错别字、颜色微调 |

### 4.2 问题记录模板

每个问题记录以下信息：
```
【问题编号】BUG-XXX
【发现时间】YYYY-MM-DD
【问题级别】P0/P1/P2/P3
【问题模块】简历生成/匹配评估/岗位抓取/...
【问题描述】详细描述问题现象
【复现步骤】1. ... 2. ... 3. ...
【预期结果】应该是什么样的
【实际结果】实际是什么样的
【环境信息】操作系统/Python版本/浏览器版本
【附件】截图/日志/错误信息
【状态】新建/已确认/修复中/已修复/已验证/已关闭
【修复版本】vX.X.X
【备注】其他需要说明的信息
```

### 4.3 整改流程

1. **问题发现**：在实战测试中发现问题，按照模板记录
2. **问题确认**：复现问题，确认级别和影响范围
3. **问题修复**：
   - P0问题：立即修复，提交紧急补丁
   - P1问题：24小时内修复，提交常规更新
   - P2问题：3天内修复，合并到下一个版本
   - P3问题：收集多个后统一修复
4. **修复验证**：修复后重新测试，确认问题解决
5. **回归测试**：运行自动化测试，确保修复没有引入新问题
6. **版本发布**：修复验证通过后，提交Git，更新版本号
7. **问题关闭**：验证通过后关闭问题记录

### 4.4 问题记录位置

- 创建`tests/bug_tracker.md`文件，记录所有发现的问题
- 每个问题一个条目，按照发现时间排序
- 定期回顾问题记录，分析问题分布和趋势

## 五、持续优化机制

### 5.1 版本管理

- **版本号规则**：v主版本.次版本.修订号
  - 主版本：重大架构变更
  - 次版本：新增功能、重大优化
  - 修订号：Bug修复、小优化
- **当前版本**：v1.0.0（规范化整改完成）
- **Git标签**：每个重要版本打Git标签，便于回滚

### 5.2 定期回顾

- **每周回顾**：回顾本周发现的问题、修复情况、用户反馈
- **每月回顾**：分析问题趋势、功能使用频率、优化方向
- **版本回顾**：每个版本发布后，回顾版本目标完成情况

### 5.3 用户反馈收集

- **使用体验反馈**：记录使用过程中的顺畅点和卡点
- **功能需求反馈**：记录希望新增或改进的功能
- **文档反馈**：记录文档中不准确、不清晰的地方
- **性能反馈**：记录速度慢、卡顿的场景

### 5.4 优化优先级

根据以下因素确定优化优先级：
1. **用户影响**：影响多少用户、影响程度多大
2. **使用频率**：功能使用频率高低
3. **修复难度**：修复成本和风险
4. **业务价值**：优化后带来的价值
