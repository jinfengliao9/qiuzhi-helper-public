# SOP-003：定制简历生成标准操作流程

## 目的

根据目标岗位的JD，生成定制化的简历，突出与岗位相关的经历和技能，提高匹配度。

## 前置条件

1. 已完成职位匹配评估（SOP-002）
2. 用户确认需要生成定制简历
3. `resume_data.json`简历数据源已存在

## 操作步骤

### 步骤1：分析JD关键词

1. 从JD中提取核心技能关键词
2. 识别岗位要求的硬技能和软技能
3. 确定需要在简历中突出的经历

### 步骤2：调整简历内容

1. 调整经历的描述顺序，与岗位最相关的经历放最前面
2. 使用JD中的关键词描述自己的经历
3. 突出与岗位相关的技能和项目经验
4. 精简与岗位无关的内容

### 步骤3：生成定制简历

```bash
python job_search.py apply --jd job_description.txt
```

脚本会：
1. 解析JD，提取关键词和要求
2. 进行匹配度评估
3. 根据匹配结果调整简历内容
4. 生成4套模板的HTML+PDF简历

### 步骤4：验证定制简历

1. 检查简历内容是否突出了与岗位相关的经历
2. 检查是否使用了JD中的关键词
3. 检查简历是否控制在一页
4. 检查格式是否正确

## 验证方法

1. 匹配度评估通过
2. 简历内容与JD相关
3. 关键词覆盖率高
4. 格式正确，内容完整

# SOP-004：面试准备标准操作流程

## 目的

为目标公司和岗位生成定制化的面试准备材料，包括自我介绍、面试问题、回答思路。

## 前置条件

1. 已收到面试通知或确定面试目标
2. 已知公司名称和岗位名称
3. `resume_data.json`简历数据源已存在

## 操作步骤

### 步骤1：收集面试信息

1. 公司名称、岗位名称
2. 面试形式（电话/视频/现场）
3. 面试轮次
4. 已知的面试方向（如有）

### 步骤2：生成面试准备材料

```bash
python job_search.py interview --company "公司名" --position "岗位名"
```

脚本会：
1. 分析岗位类型（GIS工程师/地籍测绘/工程测量/遥感航测/通用测绘）
2. 生成定制版自我介绍（3分钟，结合简历和目标岗位）
3. 生成针对性面试问题（约25道），分5类：
   - 专业知识题
   - 软件操作题（ArcGIS/CASS/ENVI/Python等）
   - 仪器操作题（RTK/全站仪/水准仪/无人机等）
   - 项目经验题（STAR法则相关问题）
   - 行为面试题（职业规划、团队协作、学习能力等）
4. 提供反问环节建议和面试注意事项

### 步骤3：参考面试题库

同时参考以下题库：
- `interview-prep/测绘工程面试题库.md`（71道专业面试题+回答思路）
- `interview-prep/经历深挖面试题库.md`（41道针对具体经历的定制题+回答技巧）

### 步骤4：模拟面试（可选）

如用户需要，进行模拟面试：
1. AI扮演面试官，逐题提问
2. 用户回答后，AI给出点评和改进建议
3. 重点练习自我介绍、项目经历描述、专业知识问答

## 验证方法

1. 自我介绍在3分钟内可流畅说完
2. 面试问题覆盖专业知识、软件操作、项目经验、行为面试
3. 回答思路清晰，有具体案例支撑
4. 结合用户实际经历，不编造

# SOP-005：申请归档标准操作流程

## 目的

管理投递记录和申请状态，跟踪投递进展，分析投递效果，优化投递策略。

## 前置条件

1. 已投递或准备投递新的公司/岗位
2. 工作区目录已初始化

## 操作步骤

### 步骤1：添加投递记录

```bash
python job_search.py outcome add --company "公司名" --position "岗位名" --city "城市" --source "渠道" --cv "使用的简历模板" --salary "薪资" --status "已投递"
```

必填：公司名、岗位名
选填：城市、投递渠道、使用的简历模板、薪资、JD链接、备注、投递日期、状态
默认状态：已投递，默认日期：当天
自动生成唯一编号ID

### 步骤2：更新投递状态

```bash
python job_search.py outcome update --id <编号> --status <新状态> --note "备注"
```

状态可选：待投递/已投递/笔试中/面试中/已offer/已拒绝/无回应
自动记录状态变更历史（日期、状态、备注）

### 步骤3：查看投递记录

```bash
python job_search.py outcome list              # 查看全部记录
python job_search.py outcome list --status "面试中"  # 按状态筛选
```

按投递日期倒序排列，显示：ID、公司、岗位、城市、日期、状态

### 步骤4：统计分析

```bash
python job_search.py outcome stats     # 命令行统计
python job_search.py outcome report    # 生成HTML统计报告
```

统计内容：
- 总投递数、各状态分布
- 进行中数量、offer数量、拒绝数量、无回应数量
- 关键指标：面试转化率、offer率
- 按投递渠道、使用简历版本分类统计
- HTML报告保存在`applications/投递统计报告.html`

### 步骤5：反馈闭环

1. 当收到拒绝通知时，询问拒绝原因（如有），记录到备注中
2. 定期回顾投递数据，分析：
   - 哪些渠道回复率高 → 增加该渠道投递
   - 哪些简历模板面试转化率高 → 优先使用该模板
   - 哪些类型岗位匹配度高 → 聚焦该方向
3. 将分析结果反馈给用户，优化后续投递策略

## 验证方法

1. 投递记录信息完整
2. 状态变更历史记录准确
3. 统计数据与实际记录一致
4. 拒绝原因记录有助于后续优化

# SOP-007：报告生成标准操作流程

## 目的

生成岗位推荐报告和匹配度报告，确保报告格式统一、内容完整、链接有效。

## 前置条件

1. 岗位库`jobs.json`已存在且数据已标准化
2. 匹配度已计算完成
3. 统一报告样式`templates/report_style.css`已存在

## 操作步骤

### 步骤1：验证岗位库数据

```bash
python job_search.py quality jobs
```

检查：
- 所有岗位是否通过Schema验证
- 是否有缺少必填字段的岗位
- 是否有重复岗位
- 链接是否有效

### 步骤2：生成岗位推荐报告

```bash
python job_search.py jobs report
```

报告包含：
- 岗位统计（总数、平台分布、匹配度分布）
- 高匹配岗位列表（按匹配度排序）
- 每个岗位的详情和匹配度分析
- 操作按钮（查看岗位、搜索公司）

### 步骤3：验证报告质量

```bash
python job_search.py quality report
```

检查：
- HTML结构是否完整
- 链接是否有效（无#或空链接）
- 岗位卡片数量是否正确
- 匹配度是否显示
- 操作按钮是否存在

### 步骤4：人工检查报告

1. 用浏览器打开报告HTML文件
2. 检查样式是否正确（颜色、布局、字体）
3. 检查岗位信息是否完整
4. 点击"查看岗位"按钮，确认链接可访问
5. 点击"搜索公司"按钮，确认链接可访问

## 验证方法

1. 数据验证通过
2. 报告质量检查通过
3. 人工检查样式和内容正确
4. 所有链接可访问

## 常见问题

### Q1：报告中的公司链接无法访问

**A**：公司详情页需要公司ID，无法直接生成。已修复为使用搜索链接：
- 智联招聘：`https://sou.zhaopin.com/?jl=765&kw={公司名}`
- BOSS直聘：`https://www.zhipin.com/web/geek/jobs?query={公司名}`

### Q2：报告样式不统一

**A**：确保使用统一的报告生成脚本`report_generator.py`和统一样式文件`templates/report_style.css`。不要使用临时脚本生成报告。

# SOP-008：数据验证标准操作流程

## 目的

验证数据格式和业务逻辑，确保数据质量，防止问题传递到下一步。

## 前置条件

1. 工作区目录已初始化
2. 需要验证的数据文件已存在

## 操作步骤

### 步骤1：运行数据验证

```bash
python job_search.py validate
```

验证内容：
1. 简历数据验证（Schema + 业务逻辑）
2. 岗位库验证（Schema + 批量验证 + 重复检测）
3. 申请记录验证（Schema + 状态历史）

### 步骤2：查看验证结果

- 如全部通过，显示"所有数据验证通过"
- 如有问题，显示具体问题和位置

### 步骤3：修复数据问题

根据验证结果修复数据：
1. 缺少必填字段 → 补充字段
2. 格式不正确 → 修正格式
3. 重复数据 → 去重
4. 链接无效 → 修复或替换链接

### 步骤4：重新验证

修复后重新运行验证，确保所有问题已解决。

## 验证方法

1. `python job_search.py validate` 全部通过
2. 无错误、无警告（或警告已确认可接受）
3. 数据格式符合Schema定义
4. 业务逻辑正确

# SOP-009：质量检查标准操作流程

## 目的

运行完整的质量门禁检查，确保所有模块质量达标，问题不传递到下一步。

## 前置条件

1. 工作区目录已初始化
2. `utils/quality_gate.py`质量门禁模块已存在

## 操作步骤

### 步骤1：运行完整质量检查

```bash
python job_search.py quality check
```

检查内容：
1. 简历数据质量（Schema + 业务逻辑 + 内容完整性）
2. 岗位库质量（Schema + 批量验证 + 重复检测 + 链接有效性）
3. 申请记录质量（Schema + 状态历史）
4. 配置质量（完整性 + 权重总和 + 平台配置）

### 步骤2：查看检查结果

- 显示每个模块的检查状态（通过/失败）
- 显示错误和警告详情
- 显示统计信息（通过数、失败数、警告数）

### 步骤3：专项检查（可选）

```bash
python job_search.py quality resume   # 检查简历数据质量
python job_search.py quality jobs     # 检查岗位库质量
python job_search.py quality report   # 检查报告质量
```

### 步骤4：修复质量问题

根据检查结果修复问题：
1. 数据问题 → 修复数据
2. 配置问题 → 修复配置
3. 报告问题 → 重新生成报告

### 步骤5：重新检查

修复后重新运行质量检查，确保所有问题已解决。

## 验证方法

1. `python job_search.py quality check` 全部通过
2. 0错误，0警告（或警告已确认可接受）
3. 所有模块质量达标
4. 问题不传递到下一步

# SOP-010：配置管理标准操作流程

## 目的

管理`config.yaml`配置文件，确保配置完整、正确、可维护。

## 前置条件

1. 工作区目录已初始化
2. `config.yaml`配置文件已存在
3. `utils/config.py`配置加载工具已存在

## 操作步骤

### 步骤1：查看当前配置

```bash
python job_search.py config show
```

显示配置摘要：
- 配置版本
- 工作区目录
- 抓取配置（默认平台、默认数量、详情间隔）
- 已启用平台
- 匹配权重
- 已启用简历模板
- 配置验证结果

### 步骤2：验证配置

```bash
python job_search.py config validate
```

检查：
- 必要section是否完整
- 匹配权重总和是否为1.0
- 平台配置是否完整
- 简历模板配置是否正确

### 步骤3：修改配置

直接编辑`config.yaml`文件，修改需要调整的配置项。

配置文件包含10个section：
1. `general`：通用配置（版本、工作区目录）
2. `paths`：路径配置（数据文件、输出目录）
3. `scraper`：抓取配置（默认平台、默认数量、详情间隔、反爬策略）
4. `platforms`：平台配置（智联招聘、BOSS直聘的搜索URL、启用状态）
5. `matching`：匹配配置（权重、阈值）
6. `report`：报告配置（样式、输出路径）
7. `resume`：简历配置（启用的模板、输出路径）
8. `interview`：面试配置（题库路径、问题数量）
9. `validation`：验证配置（严格模式、启用的验证项）
10. `version`：版本信息

### 步骤4：重新加载配置

修改后，重新运行配置命令，确认修改生效：
```bash
python job_search.py config show
```

### 步骤5：测试配置

使用修改后的配置运行相关功能，确认配置生效：
```bash
python job_search.py jobs report   # 测试报告配置
python job_search.py resume        # 测试简历配置
```

## 验证方法

1. `python job_search.py config validate` 通过
2. 配置修改后功能正常
3. 匹配权重总和为1.0
4. 平台配置完整

## 常见问题

### Q1：配置修改后不生效

**A**：配置加载工具带有缓存，修改后需要重新运行命令。如仍不生效，检查配置文件格式是否正确（YAML格式）。

### Q2：匹配权重总和不为1.0

**A**：修改`config.yaml`中`matching.weights`的权重值，确保总和为1.0。运行`python job_search.py config validate`验证。

### Q3：如何添加新平台

**A**：在`config.yaml`的`platforms` section中添加新平台配置，包括：
- `enabled`：是否启用
- `search_url`：搜索页面URL
- `detail_interval`：详情页访问间隔
- 其他平台特定配置

添加后运行`python job_search.py config validate`验证配置。
