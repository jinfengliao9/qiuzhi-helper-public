# SOP-006：岗位采集标准操作流程（Edge 扩展被动采集 · v0.2.0 主路径）

## 目的

用**用户本人 Edge 浏览器 + 原生解压扩展**被动采集招聘平台岗位（BOSS直聘、智联招聘），替代旧的 Browser Use/CDP 自动化方案，做到更快、更稳、几乎不触发风控。

**核心原则：用户负责搜索/筛选/翻页/导出，AI 只负责解析、匹配、出报告；AI 不自动操作浏览器、不自动投递/打招呼。**

## 前置条件

1. 用户 Edge 已加载扩展 `boss_api/boss_collector_extension/`（edge://extensions → 开发者模式 → 加载解压缩的扩展 → 选该文件夹）
2. 扩展 content.js 运行在 MAIN world、`document_start`，匹配 `*.zhipin.com` 与 `*.zhaopin.com`
3. 用户已在 **Edge 本人浏览器**登录目标平台（不是内置 Browser Use 浏览器）
4. 用户在线（BOSS 补全 JD 时需要，遇验证页要人工处理）
5. 已确定搜索关键词与筛选条件

## 架构原理（为什么这样不触发风控）

- 扩展 hook 页面自身的 `fetch`/`XMLHttpRequest`，**只镜像页面本来就会收到的响应**，不主动构造抓取请求、不自动翻页；
- 列表数据是页面正常浏览时服务器正常下发的，扩展只是"在旁边抄一份"，行为与真人浏览一致；
- 唯一的主动请求是 BOSS"补全JD"（列表本身不含长描述），用页面自身 fetch + 6-11秒拟人间隔 + 每10个长休息 + 可随时停止；
- 旧 Browser Use 走 CDP，会暴露 `navigator.webdriver`、`Runtime.Enable` 等自动化特征，被 BOSS 检测后清 token、反复跳验证页（"页面跳动"），**已归档，不再使用**。

## 反爬风险控制策略

### 智联招聘
- 列表响应已内嵌完整 JD（`jobDetailData.position.desc.description`），**纯被动、零额外请求**，正常翻页即可，无额外风控压力。

### BOSS直聘
- 列表纯被动累积；
- "补全JD"：每个详情间隔 **6-11 秒随机**，每处理 10 个额外休息 **15-25 秒**，可随时"停止补全"，已补的不重复；
- 补全时让该 BOSS 标签保持前台（后台标签会被浏览器降速）；
- 单次建议 30-60 个，不追求一次抓全；
- 一旦弹出安全验证/验证码，**立即停止，当天不再补**。

### 通用原则
- 用户在线时进行，不自动后台跑；
- 绝不自动投递/打招呼；
- 扩展代码改动后，在 edge://extensions 点"重新加载"，并 F5 刷新页面；
- 采集状态按标签页隔离，跨平台分标签导出，AI 侧多文件合并。

## 操作步骤

### 步骤1：确认需求（AI）
1. 确认平台（BOSS/智联，可多选）、关键词（"测绘/测量/GIS/遥感"，提示"测量"较宽泛）
2. 确认筛选：城市、薪资、学历、经验、公司规模/性质
3. 确认数量与去向：**独立报告（不入库）** 还是 **并入岗位库 jobs.json**

### 步骤2：用户在 Edge 设置筛选（方案A 抓取前筛选）
1. 用户在 Edge 打开平台搜索页，输入关键词
2. **由用户本人**在页面上点选城市/薪资/学历/经验等筛选条件（AI 不代点）
3. 确认右上角出现"🎯 双平台采集"面板，且对应平台计数为 0

### 步骤3：用户搜索/翻页，扩展被动累积
1. 用户正常浏览、滚动、点"下一页"，面板计数随结果增加，自动按岗位ID去重
2. BOSS 需要滚动加载更多；智联正常翻页
3. 达到目标数量后停止翻页

### 步骤4：BOSS 补全完整 JD（仅 BOSS，可选但推荐）
1. 在 BOSS 标签点橙色"补全BOSS的JD"
2. 面板显示"补全中 x/y ✓成功 ✗失败"，保持标签前台
3. 可随时点"停止补全"；智联跳过本步（列表自带JD）

### 步骤5：用户导出 JSON
1. 点"导出JSON"，得到 `岗位采集_BOSSxx_智联xx_时间.json`
2. 用户把文件本地路径发给 AI
3. 多平台时：BOSS 标签、智联标签分别导出（状态按标签隔离）

### 步骤6：AI 解析（只做数据映射，不联网）
- BOSS：`boss_api/parse_joblist_api.py`（extract_jobs/dedupe）
- 智联：`boss_api/parse_zhaopin_api.py`（parse_zhaopin）
- 解析后核对覆盖率：岗位名/公司/明文薪资/城市/JD/链接，应接近 100%；缺项要查原始字段

### 步骤7：匹配 + 出报告（按步骤1确认的去向）

**A. 独立报告（默认，测试用，不写岗位库）——优先走统一引擎**
```bash
python job_search.py collect <导出1.json> [导出2.json ...] -o applications/xxx.html
```
- 支持一次传多个 JSON，自动跨文件/跨平台合并去重
- 按 resume_data.json 做5维度评分；相对路径自动回退工作区根目录、兼容带 BOM 的导出
- 用 present_files 交付（等价底层脚本 `boss_api/make_standalone_report.py`，向后保留）

**B. 并入岗位库（正式积累）**
```bash
# 分步执行，不要用 all（会超时）
python job_pipeline.py import    # 解析后导入 jobs.json，去重
python job_pipeline.py rank      # 批量匹配评分
python job_pipeline.py report    # 出正式岗位推荐报告
```

### 步骤8：链接核对（交付前必查）
- "查看岗位"必须跳**岗位详情页**（BOSS=job_detail/，智联=jobs.zhaopin.com）
- "搜索公司"必须跳**公司主页**（BOSS=gongsi/{brandId}，智联=company.zhaopin.com 或 xiaoyuan.zhaopin.com/company）
- 不允许"搜索公司"跳到搜岗位结果页（report_generator 已修为优先用岗位自带 company_link）

### 步骤9：用户人工投递
- AI 不自动投递；用户看报告与完整 JD 后，自行到平台手动打招呼/投递。

## 验证方法

1. **采集验证**：面板计数与页面结果条数一致，导出 JSON 能被解析器 100% 解析
2. **JD 验证**：BOSS 补全后文件名含"含JD数"，智联应 100% 带 detail_text
3. **链接验证**：脚本统计报告中"查看岗位→岗位页""搜索公司→公司主页"的数量，0 个搜索页、0 死链
4. **去重验证**：跨文件合并后无重复（同平台同岗位号只留一条）
5. **入库验证**：入库后 jobs.json 通过 Schema 校验，数量只增不重复

## 常见问题

### Q1：右上角看不到采集面板
**A**：① edge://extensions 确认扩展已启用且"重新加载"过；② 页面按 F5 整页刷新（必须 document_start 前注入）；③ 确认当前域名在 matches 内（zhipin.com / zhaopin.com）。

### Q2：翻页了但计数不涨
**A**：① 可能本页结果已被去重；② 该平台搜索接口路径特殊，扩展的 URL 特征没命中——把当前搜索页 URL 和一份导出 JSON 发 AI，扩展识别规则需要按真实接口补；③ 打开 F12 Network 确认列表是 XHR/fetch 返回 JSON（扩展只 hook 这两种）。

### Q3：BOSS 补全 JD 很慢
**A**：这是刻意的拟人节奏（6-11秒/个）防风控。可以：少抓点、中途停止（已补的保留，下次只补缺失的）、保持标签前台。不要调快。

### Q4：BOSS 页面一直跳动/要求验证
**A**：说明触发风控，立即停止补全、导航到 about:blank，当天不再操作；次日再试。不要注入反检测脚本对抗（反而加重检测）。

### Q5：BOSS 和智联能合并成一份报告吗
**A**：扩展状态按标签页隔离，请在两个平台标签分别导出 JSON，然后把多个文件一起交给 `make_standalone_report.py`，自动合并去重。

### Q6：扩展代码更新后要做什么
**A**：edge://extensions 点该扩展的"重新加载"图标，再 F5 刷新平台页面；manifest 若改了 matches，可能需要重新"加载解压缩的扩展"。

### Q7：跨平台同一岗位保留哪个
**A**：以"公司+岗位/岗位号"去重，同一岗位多平台都有时优先保留信息更全的版本（BOSS 有独立详情、智联列表自带JD，按完整度择优），并记录来源。

## 安全注意事项

1. **绝不自动投递/打招呼**：只采集，投递由用户人工决策
2. **补 JD 控制频率**：严格拟人间隔，遇验证立即停
3. **用户本人浏览器操作**：不用内置 Browser Use 登录 BOSS（CDP 登录是死路）
4. **数据隐私**：采集结果仅用于个人求职，不传播、不商用
5. **JSON 用 Python 解析**：不要用 PowerShell ConvertFrom-Json 处理 UTF-8 中文（会乱码）

## 已归档方案（备查，不再执行）

- **Browser Use/CDP 自动化抓取**：触发 BOSS 风控、页面跳动、无法在内置浏览器登录，相关旧脚本（job_collector.py / multi_keyword_search.py / scraper_config.py / jd_parser.py）保留但不作采集主路径。
- 全自动爬虫、脱离浏览器直调内部API、纯半自动复制JD：均已放弃，理由见 SKILL.md 流程六。
